Quickstart: Create, Style, Publish

In ~10 minutes you’ll create your first project, add a page, style a section’s background, and see where to deploy it.

Prereqs: use a desktop‑width viewport to see the top toolbar (Tailwind & Manipulation).
  1. Create a project
    Open Projects (left rail) → Create. Give it a friendly name in Settings & More → Project Title.
  2. See pages/index.html load
  3. Delete the placeholder and create your first div
    Select the placeholder element that says "Page intentionally left blank."
    Click placeholder element then: Top toolbar → Manipulation → Delete (cross icon).
  4. Insert a section to style
    Top toolbar → Manipulation → Create → Inside. Select <section> from the tag dropdown.
  5. Give it a background color
    Switch to the Tailwind toolbar → Back Color (pick a hue) → Back Shade (e.g., 500). You’ll see background change immediately.
    Alternate: open the Styles panel (left raild) → “add class” → type bg-blue-500.
  6. Preview & publish (later)
    For now, note that the Deploy flow lives under Settings & More → Deploy to Netlify. We’ll cover it in detail below.
What you learned
  • Projects vs Files vs Designer.
  • Two ways to style: Tailwind menus or Styles panel.
  • Where the Deploy flow lives.

Building Pages

Select, navigate, and restructure quickly; then edit text and media.

1) Navigate selection
  • Manipulation → Cursor: Parent, Next, Previous, First/Last Child.
  • Optional Vim/arrow keys: h (left arrow key) parent, j (down arrow key) next, k (up arrow key) previous, l (right arrow key)/L child/last child.
2) Restructure fast
  • Manipulation → Create: Inside, Inside (last), After, Before.
  • Wrap gathers selection into a new parent; Unwrap removes a wrapper.
  • Use Delete/Copy buttons in the toolbar for quick cleanup and duplication.
3) Edit content
  • Text & Media → Single line / Multiline to replace text nodes.
  • Links: Link URL on anchors (<a>).
  • Images & backgrounds: Media URL, Media Gallery, and Background URL/Gallery.
4) Style with Tailwind
  • Font Family (includes Google Fonts search), Text Size/Style/Tracking.
  • Text Color + Shade; Back Color + Shade.
  • Or add classes directly via the Styles panel (supports inline editing/renaming).

Files & Editing

Create/rename/delete: use the Files panel controls. Protected items are hidden from rename/delete.

Drag & drop: rearrange files/folders; the UI shows valid drop targets as you drag.

Media preview: selecting images/videos/audio opens a live preview pane.

Code editor: non‑HTML text files open in a code area. Use it for scripts, JSON, etc.

Interactivity

You can add logic via declarative attributes—no manual DOM plumbing.

A. Conditional rendering (wf‑if)
  1. Select an element you want to show/hide.
  2. Toolbar → JavaScript → Conditional and set an expression (e.g., state.app.ready).
Effect: the element toggles in/out when the expression truthiness changes.
B. Lists (wf‑map)
  1. Insert a container where items should render.
  2. Toolbar → JavaScript → Map and set item of state.todos.
  3. Inside it, use mustache to show fields: {{item.text}}.
C. Events (wf‑on*)
  1. Select a button or input.
  2. Toolbar → JavaScript → Event Handlers, e.g., set click to post('app.save').
Tip: Handler values are expressions (not statements). For complex flows, call actions (post('ctrl.action')).
D. Forms
  • Placeholder (Element → Placeholder) for inputs/textarea.
  • Set Input Value to bind values (two‑way with wf‑value).
  • Form Method (GET/POST) when a form is selected.

Global & Project Settings

Wallpaper & brand: define a background URL for the editor; toggle brand canvas visibility when nothing is open.

Titles: set Project Title and Page Title for clarity in the header/HTML <title>.

Toolbar: hidden on small screens; show/hide on desktop via Settings.

Vim: enable Vim keybindings for selection navigation.

Per‑project options: NerdFonts, Tailwind, Better Chrome Scrollbars, Peacock (accent).

Netlify Deploys

Publish in minutes. Use Preview for drafts and Production for your real site.

  1. Open Deploy to Netlify (Settings & More). If prompted, set the Netlify API key.
  2. Select an existing site or choose Create new site and enter a name.
  3. Pick Production or Deploy Preview and click Deploy.
  4. Use the post‑deploy dialog to open Preview/Production links (and copy them for sharing).
Tip: Keep Preview deploys for feature branches. Switch to Production once you’re happy.

Git & ZIP Import/Export

Import Git (HTTPS)
  1. Settings & More → Import Git (HTTPS).
  2. Paste the repo URL. Wait for branches; pick one.
  3. Provide a project name if requested, then Import.
Import / Export ZIP
  • Import ZIP to load an archive into your project space.
  • Export ZIP to share or back up your project quickly.

Realtime Collaboration

Invite others to co‑edit with presence and a collab‑aware toolbar.

  1. If available, open Collaborate in Settings & More to get a share link.
  2. Send the link to your peer. They’ll open a collab UI that shows presence and selection state.
  3. Footer indicates “Awaiting collaborators…” or “Collaborating with N peers.”
Note: Some setups require Cross‑origin isolation for RTC; toggle it in Settings when available.

Companion, Shell, Companion FS

Enable Companion in Settings to unlock the Shell (integrated terminal).

The Shell panel supports multiple tabs. If authentication fails, you’ll see a warning row with a Retry button and guidance to reconfigure the key.

Companion FS can store the project via the Companion’s filesystem—toggle it per project in Settings.

Database Collections

Organize collections of data for your app.

  • Create, rename, or delete collections from the DB panel.
  • Select a collection to view/edit (when your setup supports editing the data shape).

Tips & Shortcuts

Keyboard
  • Undo / Redo: Ctrl‑Z / Ctrl‑Y.
  • Vim movement (optional): h j k l L.
Troubleshooting
  • Toolbar missing? Switch to a desktop width or show the toolbar in Settings.
  • Busy spinner? Wait for operations to complete; avoid rapid, conflicting actions.
  • Companion auth fail? Use Retry or reconfigure the key in Settings.
Examples
Expressions you might set in dialogs: 

wf-if:          state.app.ready
wf-map:         item of state.items
wf-onclick:     post('app.addItem')
wf-disabled:    !form.valid
